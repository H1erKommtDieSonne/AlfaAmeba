# Подбор по потребности и динамический чек-лист

Первая версия реализована локально в `feature/needs-checklist`. Это демонстрационная логика по исследованию BUSINESS_CREDIT_RESEARCH.md, а не утверждённые банковские требования. Ставки, вероятность одобрения и реальная проверка документов не рассчитываются.

## Сценарий

1. Клиент выбирает задачу на втором шаге заявки; для кассового разрыва и долгов появляются уточнения.
2. Сервер предлагает варианты с объяснениями, диапазонами из каталога и доступностью подачи. Сумма, срок и активность продукта учитываются при подборе и повторно проверяются при отправке.
3. Клиент выбирает продукт. На третьем шаге появляются отдельные поля для необходимых документов. Залог добавляет отдельное требование. Не относящиеся к текущему продукту уже выбранные файлы остаются дополнительными.
4. Заявка сохраняет потребность, рекомендацию, версию правил и состав пакета. Загрузка файла не означает его принятие банком.
5. При доработке типизированные документы предыдущей версии используются повторно, если в соответствующем пункте не загружена замена. Новая загрузка заменяет весь пункт только в новой версии. Старые версии неизменны. Нетипизированные старые файлы сохраняются как дополнительные, но не закрывают новые обязательные требования.

## Каталог и ограничения

`seed_demo` добавляет инвестиционный кредит и рефинансирование к оборотному и контрактному. Команда предназначена для локального демо: она также создаёт/обновляет демонстрационных пользователей.

Овердрафт, факторинг, лизинг и кредитная линия пока только справочные рекомендации. Добавление одноимённой записи в каталог само по себе недостаточно: перед включением подачи необходимо определить соответствующие поля, сроки, требования и тесты.

При просрочке, долгах поставщикам и отсутствии понятного источника погашения система предлагает разбор с сотрудником без автоматического выбора продукта. Отдельный маршрут записи на консультацию пока не реализован.

Пакеты первой версии:

- Оборотный: выписка.
- Контрактный: выписка, контракт с приложениями.
- Инвестиционный: выписка, смета/предложение поставщика.
- Рефинансирование: выписка, кредитные договоры/графики/остатки.
- При заявленном залоге: документы на обеспечение.

Это сокращённые демо-пакеты. В production нужны согласованные правила по банку, форме бизнеса, налоговому режиму и сделке, сроки актуальности и допустимые замены. Текущие ограничения загрузки: 20 МБ на файл, 50 МБ на пакет, включая повторно используемые файлы. Проверка расширения и размера не заменяет проверку содержимого и антивирусную обработку.

## Точки расширения

- `products/advisor.py`: единые серверные правила подбора и состава пакета, `RULES_VERSION`.
- `applications/advisor_forms.py`: структурированные ответы клиента.
- `applications/forms.py`: проверка соответствия продукта и комплектности, загрузки и повторное использование файлов.
- `ApplicationVersion.snapshot`: поля `needs`, `recommendation`, `checklist`.
- `ApplicationDocument.requirement_code`: заявленное клиентом назначение файла, не результат распознавания.
- API очереди возвращает `requirement_code` и снимок заявки; существующий протокол claim/download/complete сохранён.

Следующий этап уже реализован: локальный обработчик определяет тип по тексту, сопоставляет его с `requirement_code` и возвращает замечания с исходными фрагментами. См. [анализ документов](document-analysis.md) для запуска и ограничений. `SerializedDocument.document_type` остаётся результатом анализа, отдельным от заявленного назначения. OCR, ручное принятие и запрос конкретного документа остаются следующими задачами.

## Локальный запуск (PowerShell)

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\tailwindcss.exe -i theme/input.css -o core/static/core/css/app.css --minify
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Вход для локального демо: `business@example.test`, пароль `DemoPass123!`.

```powershell
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
node --check core/static/core/js/app.js
```
