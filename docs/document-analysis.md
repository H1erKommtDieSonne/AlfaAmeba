# Анализ документов через очередь

Реализован локальный текстовый обработчик. Он использует существующий HTTP-протокол claim → download → complete/fail, не отправляет документы во внешние сервисы и не принимает кредитных решений. Это объяснимые правила, а не подключённая LLM.

## Что работает

- Проверка размера и SHA-256 перед разбором файла.
- Извлечение текста из текстовых PDF, DOCX, XLSX и CSV (UTF-8/Windows-1251).
- Определение типа по характерным фрагментам содержимого, отдельно от имени файла и `requirement_code`, выбранного клиентом.
- Сверка предполагаемого типа с пунктом чек-листа. Неоднозначные типы требуют ручной проверки.
- Сверка только явно подписанного ИНН заявителя/заёмщика/владельца счёта. ИНН поставщика, банка и обычное поле «ИНН» автоматически не приписываются заявителю.
- Извлечение явно подписанного итога сметы/стоимости проекта в рублях. Отличие от суммы заявки показано как уточнение: возможна доля собственных средств.
- Замечания и фрагменты с номером страницы, абзаца или строки видны клиенту и банку. Исходный файл доступен только через проверку прав на заявку.
- Отдельный результат для каждого файла, в том числе повреждённого. Повреждение одного файла не блокирует анализ остальных.
- Продление аренды задачи перед файлами и сохранением результата, повторные попытки при транспортных сбоях. Последняя истёкшая попытка переводится в FAILED, а не остаётся навсегда в очереди.

## Статусы

`COMPLETED` у задачи означает, что обработчик вернул результаты, включая замечания. Это не принятие документов.

- `EXTRACTED`: текст извлечён, ограниченный набор правил не нашёл расхождений; сотрудник всё равно проверяет достоверность и достаточность.
- `NEEDS_REVIEW`: нужен другой файл, распознавание или ручная проверка.
- `MISSING`: в сохранённом чек-листе есть требование, к которому не привязан файл.

Результат хранится в существующем `SerializedDocument.payload`, версия схемы `document-checks-1`. Сводка находится в `DocumentProcessingJob.result_summary`. Статус заявки, снимок подбора и прошлые версии не меняются.

## Границы

OCR пока отсутствует: фотографии, сканы и PDF с пустой текстовой страницей направляются на ручную проверку. В PDF с текстом и изображением на одной странице извлекается только текстовый слой. DOCX с изображениями требует ручной проверки. Колонтитулы, сложные макеты и вложенные объекты не проверяются полностью. XLS не поддерживается; для XLSX с формулами нужна копия со значениями или ручная проверка. Подлинность, подписи, срок актуальности, все договоры/графики внутри пакета и финансовые показатели не удостоверяются.

Лимиты: 20 МБ файла, 50 МБ распакованного Office-документа, 100 страниц PDF, 2000 строк и 100 столбцов таблицы, 150 000 символов текста. Парсер запускается отдельным процессом с лимитом 30 секунд. Это ограничение времени, а не полноценная защита по памяти или антивирусная песочница. Для production нужны ограничения ресурсов контейнера и проверка вредоносных файлов.

## Запуск локально

Установить зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r ml/requirements.txt
```

Запустить сайт в одном терминале:

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

В другом терминале обработать одну задачу или ожидать новые:

```powershell
.\.venv\Scripts\python.exe manage.py process_documents --once
.\.venv\Scripts\python.exe manage.py process_documents --watch
```

Команда читает токен из настроек Django. Для другого локального порта используйте `--queue-url http://127.0.0.1:8001/api/v1/llm`. Если в `.env` задан токен, сервер и обработчик должны использовать одинаковое значение.

В Docker сервис `ml` теперь запускает воркер и health endpoint. Файлы получаются по внутренней сети из Django; общий доступ к media не нужен. Docker-сборку следует проверять в окружении с Docker; локальная разработка не требует Docker.

Для самостоятельного запуска воркера: `python -m ml.worker --once`; переменные `DJANGO_QUEUE_URL` и `LLM_SERVICE_TOKEN` обязательны. Ключ `--once` можно убрать для постоянной работы.

## Пример

В `docs/samples` находятся синтетические CSV для инвестиционной заявки на 1 500 000 ₽. Выписку приложите к пункту выписки, смету — к смете. После обработки у сметы появятся замечания по отличающемуся ИНН и стоимости проекта. Файлы не являются реальными банковскими документами.

```powershell
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe manage.py check
```

Тесты требуют зависимостей анализа (`pip install -e ".[dev]"` или файл requirements выше). Покрыты извлечение, повреждённые файлы, XML entities, типы, реквизиты, доступ к исходным файлам, продление аренды, исчерпание попыток и прохождение HTTP-контрактов очереди с реальным парсером.

## Дальнейшее развитие

Подключить OCR с сохранением координат и уверенности распознавания, затем при необходимости модель для сложных документов. Сохранить контракт результатов и ссылки на доказательства. Отдельно добавить принятие конкретного документа сотрудником, запрос замены и версионирование этих действий.
