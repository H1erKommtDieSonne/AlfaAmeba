# AlfaAmeba — кредитный кабинет для бизнеса

Веб-приложение для подачи и рассмотрения заявок на финансирование малого бизнеса. Клиент выбирает задачу, получает предварительный подбор продукта и прикладывает документы. Сотрудник банка проверяет заявку, изучает результаты обработки документов и финансовые показатели, запрашивает уточнения и передаёт заявку на согласование.

Основная ветка репозитория — `clean-main`.

## Возможности

### Клиентский кабинет

- Регистрация, вход по электронной почте и доступ к заявкам своей организации.
- Пошаговая заявка: реквизиты компании, потребность, продукт, сумма, срок, цель и документы.
- Подбор по задаче: закупки и текущие расходы, кассовый разрыв, расширение бизнеса, покупка оборудования, исполнение контракта или рефинансирование.
- Динамический перечень документов по выбранному продукту и наличию залога.
- Просмотр статуса, комментариев, результатов проверки и запросов дополнительных сведений.
- Повторная отправка после доработки с созданием новой версии. Документы можно перенести, заменить или исключить из новой версии, сохранив историю.

Подбор работает на версионированных правилах. Для подачи предусмотрены оборотный и контрактный кредиты, инвестиционный кредит и рефинансирование. Овердрафт, кредитная линия, факторинг и лизинг используются как справочные рекомендации; доступность подачи проверяется отдельно. Диапазоны продуктов в демо-каталоге не являются банковской офертой.

### Кабинет сотрудника

- Очередь заявок и назначение ответственного специалиста.
- Карточка клиента с параметрами заявки, версиями, документами и историей событий.
- Финансовые показатели, графики денежных потоков, источники данных и результаты внешнего узла при их наличии.
- Ввод и подтверждение параметров расчёта: ставка, платежи, отчётный год и сведения о счетах. Расчёт аннуитетного платежа по сумме, сроку и ставке.
- Просмотр замечаний к документам, недостающих данных, конфликтов и итогового текста нейросетевого анализа, если он получен от узла.
- Возврат на доработку, передача старшему согласующему, одобрение или отказ в соответствии с ролью.

### Роли и процесс рассмотрения

| Роль | Доступ |
| --- | --- |
| Представитель бизнеса | Подача и доработка заявок своей организации |
| Кредитный специалист | Обработка заявок, запрос уточнений, передача на согласование |
| Старший согласующий | Одобрение, отказ и возврат на рассмотрение |
| Администратор банка | Управление доступом пользователей и организаций |

Основной маршрут заявки:

```text
Отправлена → На рассмотрении → На согласовании → Одобрена / Отклонена
                   ↓                 ↓
          Требует доработки    На рассмотрении
                   ↓
          Новая версия заявки
```

Версия фиксирует параметры, подбор и комплект документов на момент отправки. Автоматическая обработка не заменяет действия сотрудника и не меняет заявку на «одобрена» самостоятельно.

## Документы

| Продукт | Обязательный комплект для подачи |
| --- | --- |
| Оборотный кредит | Выписка по расчётному счёту |
| Контрактный кредит | Выписка, контракт и приложения |
| Инвестиционный кредит | Выписка, смета или предложение поставщика |
| Рефинансирование | Выписка, кредитные договоры, графики и остатки долга |

При выборе залога добавляются документы на обеспечение. Годовую отчётность и другие материалы можно приложить дополнительно. Точный состав документов и периоды уточняются при рассмотрении.

Ограничения одной версии заявки:

- До **5 файлов**, включая перенесённые из предыдущей версии.
- До **10 МБ** на файл и **50 МБ** на весь пакет.
- Форматы: **PDF, PNG, JPG/JPEG, XLSX, CSV, DOCX**. Формат XLS не принимается.

Файлы сохраняются с размером и SHA-256. Скачивание защищено проверкой доступа к заявке; документы не раздаются как публичная статика.

## Обработка документов и аналитика

В проекте есть несколько отдельных механизмов обработки.

### Локальный разбор

HTTP pull-очередь передаёт воркеру документы конкретной версии заявки. Воркер проверяет размер и хеш, извлекает текст из PDF, DOCX, XLSX и CSV, сопоставляет распознанный тип с назначением файла и ищет явные несоответствия ИНН и суммы проекта. Результаты содержат замечания и ссылки на фрагменты: страницу, абзац или строку.

В локальном обработчике нет OCR: изображения и сканированные PDF требуют распознавания другим сервисом или ручной проверки. Таблицы с формулами также направляются на проверку. Извлечённый текст не означает, что документ принят сотрудником.

### Внешний финансовый узел

Модуль `node_integration` отправляет пакет документов и контекст заявки внешнему сервису, принимает callback и обратную связь, сохраняет результат для соответствующей версии и попытки обработки. Сервис узла запускается отдельно; основной Compose-файл содержит отправитель `node-sender`, но не сам узел.

Интерфейс поддерживает финансовый результат схемы v2: наблюдения с источниками, готовность входных данных, месячный денежный поток, коэффициенты, DSCR, прогноз следующего месяца и результаты годовых моделей. Доступность блоков зависит от ответа узла. Дополнительно поддерживается текстовый `final_analysis`: основные выводы, риски, недостающие данные и противоречия.

В `mlinstance/` находятся артефакт моделей, скрипт прогнозирования и адаптер контракта инференса. Django не запускает этот скрипт при подаче заявки: результаты моделей приходят от узла в составе callback. Адаптер принимает прогнозы от переданного ему `scorer` и приводит их к формату интерфейса.

Поддержаны прогноз выручки, чистая и операционная маржа, вероятности убытка и дефицита ликвидности, расчётный кредитный лимит и рекомендация модели. **Вероятность дефолта, вероятность одобрения и буквенный риск-рейтинг не рассчитываются этим контрактом и остаются незаполненными.** Расчёты и нейросетевой текст служат материалом для рассмотрения, а решение принимает сотрудник.

### Демо-аналитика

Отдельные stub-воркеры воспроизводят сценарии `normal`, `missing_data` и `manual_review` на синтетических данных. Они не извлекают финансовые факты из содержимого файлов и не запускают реальные модели. Их ответы помечены как демонстрационные.

Очереди документов и аналитики имеют отдельные сервисные токены, аренду задач и повторные попытки. Завершённые результаты привязаны к версии заявки; повторная идентичная доставка callback не создаёт новый результат.

## Технологии и структура

Python 3.12+, Django 5.2, Django Templates, Alpine.js, Tailwind CSS и Chart.js. Локальная база по умолчанию — SQLite; контейнерное окружение использует PostgreSQL 17, Gunicorn и Nginx. Для локального извлечения используются pypdf, openpyxl и defusedxml.

| Каталог | Назначение |
| --- | --- |
| `applications/` | Заявки, версии, формы и кабинеты |
| `products/` | Каталог и правила предварительного подбора |
| `organizations/`, `users/` | Организации, пользователи и права доступа |
| `documents/` | Файлы, защищённое скачивание и очередь обработки |
| `analytics/` | Очередь аналитики и хранение результатов |
| `node_integration/` | Внешний узел, callback, финансовые данные и их отображение |
| `ml/` | Локальное извлечение, HTTP-клиент очередей и демо-воркеры |
| `mlinstance/` | Модельный артефакт, скрипт прогнозирования и адаптер |
| `core/`, `theme/` | Общие компоненты интерфейса, JavaScript и стили |
| `config/`, `infra/` | Настройки Django и Nginx |
| `docs/` | Контракты интеграций, схемы и описание обработки |

## Запуск в Docker

Нужны Docker Engine или Docker Desktop с Compose и доступ к интернету для сборки образов.

```sh
git clone --branch clean-main https://github.com/H1erKommtDieSonne/AlfaAmeba.git
cd AlfaAmeba
```

Скопируйте `.env.example` в `.env` и задайте собственные `DJANGO_SECRET_KEY`, `POSTGRES_PASSWORD`, `LLM_SERVICE_TOKEN` и `ANALYTICS_SERVICE_TOKEN`. Токены двух очередей должны различаться. Для пароля базы учитывайте ограничения URL, указанные в `.env.example`.

Минимальный запуск кабинета с локальным разбором документов:

```sh
docker compose -f compose.yaml up -d --build nginx
docker compose -f compose.yaml exec django python manage.py seed_demo
```

Команда поднимает Nginx и его зависимости: Django, PostgreSQL и `ml` с локальным обработчиком. Миграции, сборка CSS и сбор статических файлов выполняются контейнерным окружением. Кабинет доступен по адресу [http://localhost:8080](http://localhost:8080); порт задаётся через `APP_PORT`.

Явный `-f compose.yaml` исключает автоматическое подключение `compose.override.yaml`, который требует заранее созданную внешнюю сеть `alfa-node-net`. Обычный `docker compose up` также запускает оба демо-воркера. Локальный и демонстрационный обработчики документов используют одну очередь, поэтому для воспроизводимой обработки выбирайте один из них.

### Подключение внешнего узла

Укажите в `.env`:

- `DOCUMENT_NODE_ENABLED=true`.
- `DOCUMENT_NODE_URL` — доступный отправителю адрес узла.
- `DOCUMENT_NODE_API_KEY` — ключ запросов Django → узел.
- `DOCUMENT_NODE_CALLBACK_TOKEN` — отдельный секрет callback узел → Django.
- При использовании провайдера отчётности — `DOCUMENT_NODE_PROVIDER_URL` и `DOCUMENT_NODE_PROVIDER_API_KEY`.

```sh
docker compose -f compose.yaml --profile node-sender up -d --build nginx node-sender
```

Узел должен иметь доступ к маршрутам `/api/v1/document-node/callback/` и `/api/v1/document-node/feedback/` приложения. Если используется поставляемый override для общей Docker-сети, создайте `alfa-node-net` и подключите к ней внешний узел; alias Django в этой сети — `django-web`.

## Локальный запуск без Docker

Создайте виртуальное окружение Python 3.12 или новее, активируйте его и установите зависимости:

```sh
python -m venv .venv
```

Активация в PowerShell: `.\.venv\Scripts\Activate.ps1`; в Linux/macOS: `source .venv/bin/activate`.

```sh
python -m pip install -e ".[dev]"
```

Скопируйте `.env.example` в `.env` и настройте секреты. Без `DATABASE_URL` используется файл `credit_scoring.db`; без явно заданного окружения — `config.settings.dev`.

Скачайте standalone-бинарник [Tailwind CSS 4.3.1](https://github.com/tailwindlabs/tailwindcss/releases/tag/v4.3.1) для своей ОС и соберите CSS. Например, в PowerShell:

```powershell
.\tailwindcss.exe -i theme/input.css -o core/static/core/css/app.css --minify
```

В Linux/macOS используйте исполняемый `./tailwindcss` с теми же аргументами. Node.js для этой сборки не нужен.

```sh
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 127.0.0.1:8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Для обработки новых документов запустите во втором терминале с тем же окружением:

```sh
python manage.py process_documents --watch
```

Для отправки во внешний настроенный узел используется отдельная команда `python manage.py send_node_jobs --watch`.

## Демонстрационные данные

`seed_demo` создаёт или обновляет каталог продуктов, пользователей и две синтетические заявки: оборотный кредит с собранным комплектом и контрактный кредит с запросом документов. В карточках есть заранее подготовленные демонстрационные результаты узла.

| Учётная запись | Роль |
| --- | --- |
| `business@example.test` | Представитель бизнеса |
| `bank@example.test` | Кредитный специалист |
| `senior@example.test` | Старший согласующий |
| `admin@example.test` | Администратор банка |

Пароль демо-пользователей — `DemoPass123!`. Эти учётные записи предназначены для локальной демонстрации; `seed_demo` не следует запускать в рабочем окружении с реальными клиентами.

## Проверки

После установки зависимостей `.[dev]`:

```sh
python manage.py check
python manage.py test
```

Проверки JavaScript-мастера заявки запускаются отдельно и требуют Node.js:

```sh
node core/tests_js/wizard.test.cjs
```
